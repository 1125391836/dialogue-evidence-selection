# 面向工具调用的对话历史压缩与参数恢复

## 用一次改订说明我们要做什么

假设用户说“订周五晚上，两个人”，过几轮又说“换成周六，其他照旧”。最后应该提交周六、晚餐、两人。把周五带回来会订错日期，漏掉最初的“两人”又可能让用户重复回答。

| 论文要回答的问题 | 实际怎么做 | 意义 |
|---|---|---|
| 这种错误值得研究吗？ | 在开发对话里标出哪些要求改了、哪些仍然有效，统计漏填、沿用旧值和多填各有多少 | 说明多少任务受到影响，识别最值得修的错误 |
| 同样只能读很短的历史，助手能多做对多少？ | 让同一个助手分别看最近消息和新方法挑的消息，逐题对照，记录救回与弄错的任务 | 把消息选择带来的收益和代价都算进去 |
| 哪一步起作用？ | 单独关掉寻找旧证据或识别后续修改的步骤，再看哪些题退步 | 判断增加的复杂度是否值得 |
| 换一个业务还能用吗？ | 先固定方法，再到未用于开发的业务里实际运行工具，核对最终订单或预订状态 | 检查能否把一次实验的改进带到新场景 |

本轮实现了一条简单规则。工具已知时，优先选择含公开可选值的原话，同类消息中优先选最近的。128 token 下，两种方法用同一个读取器。SGD 开发集各对 1,113/1,897，逐题有 9 胜 9 负。SGD 测试集从 1,502/2,684 提高到 1,526/2,684，28 胜 4 负。该测试集曾用于其他指标，此次比较属于探索性评测。计分范围为可枚举参数，开放式参数与执行结果仍待验证。

## 投稿定位

### 字段更新与跨数据集复验结果

SGD 测试集中，在同一服务和意图的连续用户状态内，296 个枚举字段有前后取值集合不相交的更新记录。最近消息答对 233 个，优先保留含可选值的消息答对 234 个。另有 2,512 个字段与上一轮一致且在该段内未检测到上述更新，两种方法分别答对 1,864 和 1,883 个。状态来自官方标注，分组属于事后诊断。把检索限制为只补最近消息遗漏的必填字段，并保留已填参数，在开发与测试集分别净增 3 道完整枚举参数题。

在首次使用的 MultiWOZ 2.2 官方测试集上，沿用同一选择器和读取器。每个对话取最后一个用户轮次，给定业务领域，在每个有枚举目标的领域分别允许 128 token 的历史。该对话中所有入选领域的枚举状态全部匹配才算正确。1,000 个对话中有 935 个进入评测。最近消息、BM25、优先保留含可选值的消息分别答对 22、36、74 个，完整历史参照答对 84 个。对最近消息有 54 胜、2 负。完整历史分数较低说明显式取值匹配读取器的局限。此处测最终对话状态，与 SGD 的服务调用参数口径有别。逐领域预算也不能解释为整段多领域对话合计 128 token。

复现可在项目根目录依次运行 `.\.venv\Scripts\python scripts\field_update_audit.py` 和 `.\.venv\Scripts\python scripts\multiwoz_transfer.py`。前者复用上一轮缓存的两组预测，后者读取已下载的官方测试文件。

## 已完成的两个实验

按共享历史组有放回重采样 10,000 次，每次保留组内整题与方法配对，统计按题加权的成功率差。128 token 下，加入工具参数说明相对 BM25，在 Mem2Act 上多赢 12 题、输 4 题，净增 9.1 个百分点，95% 百分位区间为 0.0 至 18.9。在 SGD 上多赢 619 题、输 407 题，净增 5.9 个百分点，区间为 4.2 至 7.6。相对最近消息，SGD 同一指标下降 30.8 个百分点。区间为逐项探索性区间，测试结果已看过。

在 SGD 开发集上，每段对话取最后一次服务调用。2,482 个有调用的对话中，1,897 个参考调用包含至少一个公开枚举参数。固定读取器从当前请求与可见历史中选取每个枚举字段最后一次显式出现的合法值，预测字段集合和值全部正确才计分，多填字段也扣分。已知目标工具。仅当前请求答对 61 题，128 token 下 BM25 答对 791 题，加入参数说明答对 831 题，最近消息答对 1,113 题。完整历史答对 1,114 题。该实验没有覆盖开放文本参数、隐式值和数据库状态验证，完整历史的读取器仍会犯错。

将 128 token 中的一半优先分给最近消息，用余量做参数说明检索，答对 1,115 题。与最近消息逐题比较，18 题改善、16 题退步、其余一致。案例 1_00011 中，订餐人数出现在较早的确认语句里，用户后来只修改餐厅和日期。固定配额遗漏了仍然有效的人数，最近消息基线恢复了该参数。这个案例支持把参数的分别更新作为待验证假设。固定配额已实现，后续用作强基线。

## 后续实验次序与决策

1. 在开发数据中按对话抽取成功、近因检索独胜、语义检索独胜、两者都失败四类样本。分层抽样只用于归因。标出当前意图、参数最终确认位置、冲突旧值与首次可用证据，两人独立标注并报告一致率。用各层真实权重估算总体比例。
2. 开发可替换的检索策略。先测固定一半预算保护最近交互，再用余量检索较早的用户确认及工具返回。比较同预算的最近消息、BM25、参数说明 BM25、稠密检索、固定配额混合及自适应配额。自适应决策只读对话和公开工具定义。消融分别移除近期保护、跨会话检索和确认语境。全部方法使用同一读取器和序列化预算。
3. 在开发集调试完整工具参数预测与可重置环境执行。每次保存初始状态、可见输入、预测、执行结果及最终状态。用官方参考动作作评分，记录错写、无写入、请求澄清、费用与延迟。完整历史作诊断参照。固定工具条件与自主选工具条件分表报告。
4. 在任何新方法接触最终评测样本前，登记外部数据版本、独立任务列表、排除规则、模型版本、主要比较、预算和评分脚本哈希。按任务或共享历史分组，重复轨迹仅用于稳定性分析。已查看的 Mem2Act 与 SGD 测试集用于对照与误差分析。选用经去重且未开发过的服务或任务构成确认性评测。先用开发集估计配对不一致率，按最小有应用价值的改善幅度估计所需组数。
5. 主要指标采用相同历史预算下完整工具调用参数正确率，在可执行任务上另报最终状态成功率与错写率。预先从开发集确定强基线；逐域报告配对差值和区间。如果独立样本上收益仅出现在字符串保留指标，收窄论文主张为检索评测与失效分析。若强基线在短对话已接近上限，将跨会话、用户改口和多候选指代作为预先定义的效应差异分析，并同时保留总体结果。
