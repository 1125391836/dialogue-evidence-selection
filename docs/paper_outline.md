# 论文结构与证据设计

建议工作题目为《面向工具型智能体的预算约束上下文组合选择》，英文暂用 **Budgeted Context Selection for Tool-Using Agents with Complementary Evidence**。只有数据支持强互补定义后再在标题中加入“不可分”。项目名 context-bundles 只是工程目录名，不作为创新证据。

论文应围绕一个主张展开：逐项增加内容可能跨不过关键组合的收益门槛；受限组合发现和选择在真实工具任务中能否带来同成本收益。不要把摘要、记忆恢复、工具图、时效检测等全部写成独立创新。

以下按约 8—9 页英文正文规划，最终篇幅及模板以所投会议最新要求为准。参考文献、局限性与附录按会议要求处理。

## 摘要 Abstract

用五步写：实际上下文成本；最近邻方法；通过诊断发现的具体失效；方法；真实实验结果与边界。约 150—250 英文词只是写作安排，不是统一投稿规定。

现在只写背景与待验证问题。互补频率、提升百分点、节省费用与显著性全部等待实验后填写，不能用期待的数值占位成结论。

## 1 引言 Introduction 约 1 页

先讲长任务需要保存可执行依据，但历史预算有限。用一个在公开任务中核实、能复现的失败案例展示单项选择为什么会漏掉组合。人工小例子可用于解释，必须标明，不当作现实普遍性的证据。

随后承认 MemCredit 已经做条件边际选择，MeClear 已经研究信息交互，依赖记忆与工具支持图也已有研究。研究缺口落在已验证的失败机制、受限候选发现和预算搜索，而不是“从未有人考虑相关性之外的价值”。

贡献只能在结果成立后写成：

1. 一项可复现的执行层诊断，区分组合缺失、评分门槛、冗余和普通推理失败。
2. 一种有明确计算限制的候选组合与条件集合选择方法，并给出与强基线的机制对照。
3. 跨静态依据与交互执行的成本匹配评估，说明有效和无效的边界。

推荐图 1：一个真实失败案例及四条件干预结果，展示为什么“每条单看不重要”不等于“整组不重要”。若无法找到稳定案例，应调整主张而非补一个更好看的故事。

## 2 相关工作 Related Work 约 0.75 页

按四条线组织，不逐篇罗列摘要：

- 上下文压缩与恢复：HiAgent、ACON、ACM、D-Mem、RIME、PaMER。
- 决策效用、交互归因与集合选择：MemCredit、MeClear、ConMem、BPS。
- 工具与依赖结构：MemTool、RAG-MCP、ContextWeaver、HyperAgent。
- 执行评价与成本控制：Mem2ActBench、AppWorld、ToolSandbox、ARCBench、Rethinking Tool Graph Memory。

推荐表 1：最近邻方法的选择对象、是否条件打分、如何处理组合、是否恢复、评估是否执行、额外模型开销。列“原文未报告”时须核对原文，不能把没读到当作没有。

## 3 问题定义 Problem Formulation 约 0.75 页

定义任务、历史块、固定工具定义、历史预算、实际序列化成本、任务效用及随机执行协议。给出选择目标与预算约束，明确它不保证找到真实最优集合。

定义相对背景 S 的互补性、两项单独增益和联合增益；二阶差分引用已有工作。说明静态阶段与交互阶段的 U 不同，并分别验证，不把 F1 直接等同最终任务完成。

区分三层误差：候选没有找到、价值估计不准、搜索没有选对。该区分决定后面的消融。

## 4 现象诊断 Diagnosing Complementarity 约 1 页

回答 RQ1。说明未按效果筛选的采样方式、分组划分、模型、重复次数、证据审核与四条件干预。报告候选发现率和审核后互补率的分母，避免只对“已发现的好组合”统计。

加入等长度随机组、历史位置、替代证据与参数级评分控制。排除“两个独立参数同时正确才能得 Exact Match”制造的假象。报告标注协议、分歧处理与失败案例。

推荐图 2：不同预算下的组合增益分布与置信区间。没有达到标准的样本也保留。若只是探索性证据，应如实降低结论强度。

## 5 方法 Method 约 1.25—1.5 页

5.1 候选证据与稀疏组合：输入来自真实可见历史，提取依赖候选的规则或模型，候选数限制，召回失败处理。

5.2 条件效用学习：训练环境干预如何生成标签；估计 ΔU(G|S,q) 的输入、损失、校准与负例；如何按历史组交叉验证；测试时完全不访问答案。

5.3 预算搜索：单项、组合及有限替换操作；束宽和最大评分次数；去重后的真实序列化成本；提前停止规则。展示伪代码和复杂度，不为一般非单调未知效用虚构近似保证。

5.4 恢复接口：作为所有方法共享的执行设施简要交代，不独立包装为创新。

推荐图 3：从历史候选到组合提议、价值估计、预算搜索、Agent 执行的流程。图中明确训练标签只流向训练过程，不能流向测试选择。

## 6 实验 Experiments 约 2—2.5 页

6.1 设置：数据版本、许可和使用规则、provided-context 范围、训练划分、模型与 tokenizer、预算、模板、恢复协议、API 价格日期。所有适配基线说明与原论文差别。

6.2 主结果：Mem2ActBench 的调用准确率与参数 F1；AppWorld 的任务完成率与违规/附带修改；选择器和主 Agent 的完整成本。各环境分别报告，不能把不可比的分数直接相加。

6.3 同成本对照：条件单项选择、规则补齐、简单 pair-seeding、一次性 LLM 联合选择、相关强压缩方法、随机组合及相同额外调用。

6.4 消融：固定候选比较价值预测；固定效用比较搜索；替换候选生成器比较召回。小候选池穷举只作诊断参考，不作为可部署方法。

6.5 鲁棒性：模型迁移、未见任务、不同预算、无互补样本退化，以及恢复允许/不允许的差异。

## 7 分析与局限 Analysis and Limitations 约 0.5—0.75 页

分析失败来自候选、预测、搜索还是执行器。讨论三元以上组合、非单调效用、信息过期、预测器换模型失效、静态合成数据的外部有效性，以及探索后选择假设的偏差。

如果高收益仅出现在极低预算或人为构造长历史，要明确适用范围。若普遍没有增益，这可以支持诊断型论文的重新定位，但不能继续声称完整方法有效。

## 8 结论 Conclusion 约 0.25 页

只总结已有证据支持的发现、方法和边界，不引入新结果、不承诺所有 Agent 都能改善。

## 附录与复现材料

附录收录完整提示、全部配置、数据划分规则、实现差异、超参数搜索范围、分组统计、价格表、额外预算曲线、错误案例和标注指南。按原数据许可发布任务 ID、适配代码及必要衍生数据，避免直接重发受限制内容。

代码发布应能从固定 commit 数据生成请求计划与结果表；原始运行日志与论文表格之间有可追溯脚本。所有执行过的实验，包括负结果，保留配置和状态。

## 主张与证据对应表

| 想写进论文的话 | 必须具备的证据 | 不足以支持它的东西 |
|---|---|---|
| 工具任务中存在有意义的组合缺失 | 自然任务上的干预与审核、适当分母及不确定性 | 人工 AND 小例子、只看 Exact Match |
| 新方法改善了预算选择 | 同候选同预算同模型，与条件单项和强规则比较 | 只打败最近历史或相关性排序 |
| 收益来自组合机制 | 候选、预测、搜索分开的消融与随机控制 | 更大模型、更多调用或更长上下文 |
| 方法具有实际价值 | 交互环境完成率、全部费用及恢复开销 | 静态工具参数评分 |
| 具有跨场景适用性 | 冻结配置后的未见任务或模型测试 | 同一历史的多个改写随机分到训练测试 |

## 投稿定位

以 NLP 方向的 EMNLP 或 ACL 主会长文规范准备是一条合理路线；若形成一般决策/资源分配贡献，可再评估 AAAI 或 JAIR。具体 CCF 类别、论文类型和学校认可须按投稿时正式目录核对。预印本和 Findings 不自动等于对应主会完整论文；目前不能依据选题保证录用层次。
