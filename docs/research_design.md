# 工具型 Agent 上下文组合选择研究设计

2026-11-20 补充复核：新增 SetR、OptiSet、SCAR–Pair、RepoShapley 等直接或相邻对照。通用“成组选证据、学习集合效用”已不能作为独立新颖性主张；当前方法仍未证明有效。详见 [选题复核](../../research_work/revalidation_2026-11-20/选题复核.md)，后续实验应结合这些新增对照。

本设计延续 2026 年 11 月 18 日的文献调研。目标是验证一个可被否定的假设：某些执行依据只有共同呈现时才有用，逐项正收益选择可能漏掉它们，而少量组合搜索能以合理成本改善任务完成。现已完成 58 次 DeepSeek 探索调用，但尚未建立有效性或原创性证据；具体结果见 README 和首轮 postmortem。

## 1 准确描述我们要做的事

建议表述为：**在给定上下文预算下，选择一组能够共同支持正确行动的历史信息，使预期任务效用尽可能高。**

用户提出的“保留哪些被上下文压缩后的信息组合最有价值”抓住了预算与组合，但需要两点修正。

第一，主方法在压缩或装配上下文时决定保留什么。候选信息来自仍然保存的原始历史或档案。如果信息已经不可逆地删除，选择器无法凭空恢复。第一版采用抽取式选择，暂不让模型改写证据；后续才研究已有摘要与原文混合候选。

第二，“最优”是数学目标，不是算法性能承诺。真实任务效用未知且带随机性；预测误差、候选漏召回和搜索近似都可能造成损失。正式标题暂不使用“最优”“保证完成”“首次”等词。

固定当前任务 q、工具定义 T、Agent 模型 M、执行协议 P、环境状态 x。候选历史片段为 C，选择结果 S 是 C 的子集。研究目标是最大化 U(S | q,T,M,P,x)，约束 c(S) ≤ B。

- U：固定协议下重复运行得到的预期效用。静态阶段以完整工具调用正确率为主；交互阶段以环境最终任务完成率为主。参数 F1 与违规率作为独立指标。
- c：按统一顺序序列化后的实际历史长度，包括来源 ID 与分隔符。不能把各片段独立 token 数简单相加当作精确成本。
- B：第一阶段的历史上下文预算。当前任务、系统提示和目标工具定义固定，另外报告其成本及完整请求用量。之后再研究总提示预算或工具定义共同选择。
- 费用：训练、选择器推理、主模型、摘要、检索、恢复与重试分别计量。相同历史预算不等于相同费用。

不同时改变工具集合、主模型、规划器、恢复权限和压缩策略。完整历史只是参考组，不是一定最好的上界，也不是同预算对照。

## 2 文献把创新空间限制在哪里

| 最接近的工作 | 已经做过什么 | 我们不能重复声称什么 | 需要补上的证据 |
|---|---|---|---|
| [MemCredit](https://arxiv.org/abs/2611.15600) 第 3.4 节 | 根据已选集合估计条件边际效用，指出联合才有用的记忆可能被漏掉 | 不能把它说成固定独立排序，也不能宣称首次按任务效用选记忆 | 同候选、同预测器能力下，逐项搜索是否仍受互补结构限制 |
| [MeClear](https://arxiv.org/abs/2609.09115) 式 15 | 合作归因和二阶交互诊断 | 二阶差分不是我们的新公式；信息交互不是空白 | 归因之后的预算选择能否已经解决问题，组合搜索是否有额外收益 |
| [Optimal Skill Selection](https://arxiv.org/abs/2608.19993) 第 3 节 | 有预算的集合选择与特定目标下的保证 | “把选择写成组合优化”本身不是创新 | AND 型依赖是否在实际任务出现，拟合目标与真实效用的差异有多大 |
| [HyperAgent](https://arxiv.org/abs/2608.02650) | 工具 schema、可用值、缺失前提及支持子图 | 不能宣称首次把工具与参数依据配套 | 固定规划器后，选择呈现哪些证据的作用 |
| [HiAgent](https://aclanthology.org/2025.acl-long.1575/) 与 ACM、D-Mem、RIME | 分层记忆和不同形式的按需恢复 | “丢了能找回”不能独立作贡献 | 所有对照共享恢复能力，收益仍存在 |
| [ACON](https://proceedings.mlr.press/v306/kang26b.html)、[ContextWeaver](https://arxiv.org/abs/2604.23069)、[FOCUS](https://arxiv.org/abs/2609.37590) | 面向任务、依赖和决策的压缩 | 保留执行相关信息并不是新目标 | 与适用的强压缩基线比较，并计入生成摘要的成本 |

## 3 研究问题与决策门槛

RQ1：未经按效果筛选的公开任务中，哪些失败是信息组合被拆散导致的？其发生频率、影响与预算有什么关系？

RQ2：不读取测试答案，仅依据当前任务、工具定义和可见历史，能否以有限代价发现有用的小组合？

RQ3：在相同预算及完整成本核算下，组合选择是否优于条件逐项选择、规则补齐和一次性 LLM 集合选择？

RQ4：收益是否能迁移到真正执行的多步任务、不同模型和未见场景？无互补任务上是否退化？

继续开发完整方法的条件是：现象可重复；不是只有精确匹配评分的 AND 效应；强规则或简单 pair-seeding 无法同成本解决；候选发现和推断的开销没有抵消收益。若不成立，保留诊断结果并调整研究主张，不通过删掉失败任务保留正结果。

## 4 分成三阶段开展

### 阶段 A 静态参数依据与四条件诊断

small 快照含 400 条问题和 429 个会话，现已完整保留。本轮改用同一固定 commit 的 full 快照：558 条问题、2029 个会话，显式隔离 25 条来源异常后为 533 条。数据由多源对话构造，不能当作真实部署日志。主设置提供目标工具，只研究历史信息选择与参数依据；固定工具选择减少混杂。

首先使用按共享历史划分的 train/dev 做 10 个案例的来源核查。之后预先抽取约 50 个问题做探索，正式样本量依据方差和目标效应规划。这些数字是工作安排，不是统计保证。

对一个背景 S 和候选 a、b，分别运行 S、S+a、S+b、S+a+b。所有条件使用同一模型、提示格式和历史顺序。重复运行估计 U，而不是用单次输出定义互补。可报告 I(a,b|S)=U(S+a+b)-U(S+a)-U(S+b)+U(S)，但必须引用 MeClear，不能包装成新公式。

“不可分”的强主张还需要：两项单独的增益都足够小、联合增益足够大、误差区间支持，并检查是否存在替代证据。它是相对于模型、背景、任务和时间范围的属性，不是文本永久属性。二阶正交互不能证明三阶或更高阶机制。

必须区分以下现象：两个独立参数碰巧共同决定 Exact Match；实体绑定或多跳链条需要真正组合；规则仍在但模型不遵守；信息过期；检索没找到；推理本身失败。不要把它们全叫作压缩损失。

旧 `probe-plan` 自动生成词面候选的四条件请求。新 campaign 已加入近似长度随机组，仍没有精确长度/位置控制和完整人工证据审核，不能直接产出因果结论或总体互补频率。“没有找到互补”不能直接记作“互补不存在”。

### 阶段 B 选择算法与效用预测

先使用同一完整候选历史比较 recent、BM25、普通摘要、规则补齐。四者均已实现并在首轮调用；摘要只有两题，其余三个开发题，比较时取交集。完整历史单独列为不同预算参考。

再加入条件逐项价值选择、归因后选择、集合优化、一次性 LLM 联合选择与小规模穷举参考。复现与适配要分别命名，不能把自行实现的近似版本直接当成原论文结果。

候选新方法分成四块：

1. 使用工具参数、实体提及、引用或返回值链条提出有限二元组，随后再考虑三元组。schema 只提供搜索先验，字段类型一致不等于实体一致。
2. 在训练任务的固定历史或可重置环境上做受控干预，产生条件组合净收益标签。保留正、零、负收益，不只收集成功案例。
3. 先用轻量预测器估计 ΔU(G|S,q)。推荐 Ridge/Gradient Boosting 配合简单关系和预算特征，做按历史组交叉验证；数据支持后再考虑编码器。不能把金标准参数值或其匹配特征用作测试输入。
4. 用受限束搜索或少量加入/替换操作比较单项与小组合。相同预算下对比搜索误差与价值预测误差。若简单组合种子已经足够，不再堆复杂网络。

当前 `search.py` 提供标准搜索原语，`utility.py` 已用 5 个训练组的 25 条真实观测训练 Ridge 集合效用预测器，并进行了开发组选择比较。但模型出现空集外推失真，CV 未优于常数预测，不能声称实际提升；新计划默认通过 `guards.py` 检查和回退。合成例子仍只验证搜索路径。

### 阶段 C 交互执行与外部有效性

以 AppWorld 为主候选，ToolSandbox 作为可选第二环境。预先约定触发压缩的条件，保存可重放的环境状态、历史和随机配置。所有对照从同一状态继续，不能让不同方法从各自早已分叉的轨迹做局部对比。端到端结果允许自然分叉，但需要同时保留固定状态诊断。

只删改可见历史，不修改环境真值。支持恢复时所有方法共享相同接口和预算，记录找回原文、重查工具与失败重试。环境本来就没有信息时允许澄清或停止，不评价为压缩失败。

遵守 AppWorld 官方 train/dev/test 使用规则：训练与错误分析留在 train/dev，最终 test 只用于冻结方法后的总体评价。ToolSandbox 部分场景依赖外部服务和用户模拟器，要固定配置并报告版本。

## 5 指标与公平性

主表按历史预算列完整调用正确率或任务完成率，画预算—效果曲线和总费用—效果曲线。参数 F1、工具名正确率、违规、补查、延迟和选择器开销分开报告。保留原始 API usage，费用用固定日期的价格表计算；缺失用量不能按零费用处理。

主要消融：无组合候选、随机组合、规则组合、无条件效用、条件单项效用、真实/预测效用、逐项/组合/穷举搜索、共享恢复开/关。预算、输入顺序、工具注册集合、模型输出上限及提示固定。额外调用匹配控制排除“只是多算了几次”。

重复运行先按问题汇总，再按共享历史组进行配对 cluster bootstrap。报告效应量与置信区间；同一任务多次调用不当作独立样本。该统计流程现已实现，但本轮样本极少、每条件仅一次，不能据此提出可靠显著性结论。按简单/复杂、单来源/多来源等拆分只能做预先声明的辅助分析。

保存全部 API 失败，分别报告服务失败率与方法表现。当前跑分把 API 错误计入有效服务的失败分母，同时给出错误数；论文阶段同时提供基础设施故障处理协议，避免选择性重试。

## 6 数据边界与泄漏控制

原始数据只读保存，记录仓库 commit、Git blob 校验与 SHA256。标准答案、grounding_info、evolution_chain 与难度标签不进入模型请求。当前 `cases.jsonl` 与 `labels.jsonl` 分开，API 执行器不接收标签路径。

第一版使用数据提供的 source_conversation_ids 找到相关会话，再保留这些会话的全部内容和干扰信息。这是明确的 **provided-context 诊断设置**，不是整个记忆库的无提示检索。论文须显式说明，不能声称完整复现全库检索成绩。

共享任何实际呈现的来源历史（包括干扰项）的题目属于同一连通组，整组进入 train/dev/test。当前划分是自定义研究划分，不是官方划分。记录实际组数和最大组大小；大连通组会减少有效样本量，不能强行拆开凑 70/15/15。

## 7 本轮完成与下一步

已实现：完整下载与版本校验、数据适配与历史分组、官方 tokenizer 精确预算、DeepSeek 真实执行与总额度账本、五条件探索、Ridge 效用学习、逐项/组合搜索比较、普通摘要、全成本价格核算、配对 cluster bootstrap，以及失败诊断和回退防护。

未实现：论文强基线完整复现、充分的人工证据审核与精确长度/位置控制、AppWorld 快照接入、多预算跨模型评估和正式论文图表。现有模型虽然已训练，但没有效果优势，不代表学习式方法已经研究成功。

本轮按用户选择的 DeepSeek 服务和 60 次上限已完成 58 次真实调用。下一步先修正评分协议、采样范围与预测器，再设计新的独立预算活动；当前测试集保持未评估。具体调用、用量和负结果见首轮报告与 postmortem。
