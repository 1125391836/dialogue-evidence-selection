# 在固定历史预算下保留用户决定的实验

## 购票订单

所有方法以同一 128 token 历史预算选消息，当前用户话始终可见。新规则优先保留一对包含数字、日期或时间的助手提议以及紧邻的用户改口或肯定，再按最近顺序填满剩余预算。简单相邻对照依次保留含值消息及回复。两者都属于启发式方法。五臂共享原字段读取器和整单置信度模型。分别在 247 个开发样本按目标覆盖率 20% 选阈值；既有评测队列已参与此前研究。

| 方法 | 主测正确 / 错单 / 暂缓，470 段 | 复验正确 / 错单 / 暂缓，967 段 |
|---|---:|---:|
| 最近消息 | 96 / 11 / 363 | 187 / 21 / 759 |
| 原字段选择 | 105 / 13 / 352 | 202 / 28 / 737 |
| 简单相邻 | 98 / 14 / 358 | 193 / 23 / 751 |
| 重训 Pivot | 37 / 56 / 377 | 70 / 102 / 795 |
| 确认与改口优先 | 74 / 24 / 372 | 150 / 54 / 763 |

主测新规则相对最近消息的条件错单率差为 +14.21 个百分点（24/98 对 11/107），按原生场景整组抽样的 95% 区间为 [+6.25, +27.07]。复验差为 +16.37 个百分点（54/204 对 21/208），区间 [+10.37, +27.81]。事后按每种方法置信度只取同样多的提交，复验各取 193 单，最近消息、简单相邻和新规则分别错 10、8、44 单。后一个诊断依赖整个评测批次的排名，不能直接用作线上阈值。

复验中，新规则改变了 229 段的消息选择。在提交决策前，日期从对变错 67 次、从错变对 5 次；票数分别为 63 和 9 次；场次分别为 44 和 14 次。同一订单可以涉及多个字段。优先保留一组对话会占用其他信息的预算；因果归因仍需人工充分性检验。[全量汇总和区间](ticket-summary.json) · [主测逐题](test-details.jsonl) · [复验逐题](replication-details.jsonl) · [字段及同覆盖率分析](paired-analysis.json)

Pivot 的重新实现使用固定的 BERT 和两层 MLP，在 256 段无餐厅的 SGD 对话上训练，含 5,142 条相邻轮次输入，其中 1,537 条发生字段状态变化。我们调整了训练样本、预算和任务，并沿用原有整单校准器。购票成绩不能作为对作者原任务成绩的复现或优劣判决。[协议](design.md) · [训练数据与权重摘要](pivot-training.json) · [Park 等原文](https://aclanthology.org/2026.findings-emnlp.719/)

## 跨业务与另一个读取器

以下为同一个本地 Qwen2.5-7B 读取器，参数齐备即计作提交。每组均按官方四项或整单参数严格匹配。完整历史是无预算对照。

| 方法 | SGD 餐厅正确 / 错单 / 暂缓，96 段 | Sim-R 正确 / 错单 / 暂缓，64 段 |
|---|---:|---:|
| 最近消息 | 40 / 45 / 11 | 43 / 12 / 9 |
| 简单相邻 | 35 / 51 / 10 | 45 / 11 / 8 |
| 重训 Pivot | 6 / 61 / 29 | 44 / 14 / 6 |
| 确认与改口优先 | 40 / 46 / 10 | 45 / 10 / 9 |
| 完整历史 | 27 / 66 / 3 | 57 / 7 / 0 |

SGD 从新分片的 2,023 段筛出 432 段，抽取 96 段；曾在旧项目中接触过同一服务。必填字段同时匹配为最近消息 75、新规则 74；按服务声明的默认日期和人数补齐可选项后，两者都匹配 63 单。完整历史的必填同时匹配数为 79，补默认值后完整匹配 54 单。分母均为 96。任务预先给定服务与意图。[抽样](restaurant-sampling.json) · [逐题订单](restaurant-7b-details.jsonl)

Sim-R 是独立服务和独立语料。本项在看到传统购票读取器结果后追加，测试输出产生前固定取样规则。775 段测试对话中有 116 段符合四字段成功预订等条件，抽取 64 段，仅提供成功通知之前的对话。在新规则与最近消息的配对比较中，新规则独对 2 段，最近消息独对 0 段，双侧精确 p=0.50。两种方法将场次格式归一化后成绩相同于各自的原口径。本项只观察带成功通知的预订，缺少本应禁止提交的请求。两套餐厅实验都迁移了相同的历史选择规则，读取提示和字段定义按业务提供。[抽样设计](simr-design.md) · [逐题订单](simr-7b-details.jsonl)

在旧生成式实验固定的 96 条购票对话上，7B 按原提示返回通用 JSON 时五种方法整单严格匹配均为零。查看响应发现模型常使用 movie、theater 等键名。事后使用同样的消息与提示重跑，只允许 schema 中六个原始字段名，所有字段仍可省略。最近消息、原字段、相邻、Pivot、新规则的必填项同时匹配分别为 32、34、32、10、28 单；整单匹配为 1、2、2、1、0 单。字段格式、可选参数与整单严格评分使该购票生成对照区分力较弱。[原提示逐题](movie-7b-details.jsonl) · [限定字段名逐题](movie_schema-7b-details.jsonl)

## 人工盲审

完整文本由两位读者独立标注，按已冻结协议处理分歧。压缩文本另由三位读者编码，每人 48 条，各读到 16 条最近消息、16 条原字段选择和 16 条确认与改口优先。每条对话的三个压缩版本分别给不同读者，每人只看本人的包。收到完整文本的最终结果及三份压缩回件后，运行盲评脚本，逐题对齐并报告相同场次、不同场次、材料不足和完整文本本身未定。现有人工回件为零。研究协调人保管映射表；只向读者分发其对应的 ZIP。

- [完整文本 A](../review-labels/human-v2/reviewer_A.zip) · [完整文本 B](../review-labels/human-v2/reviewer_B.zip)。返回目录为 `runs/review-labels/human-v2/returns`。
- [压缩文本 D](compressed-blind/reviewer_D.zip) · [压缩文本 E](compressed-blind/reviewer_E.zip) · [压缩文本 F](compressed-blind/reviewer_F.zip)。返回目录为 `runs/decision-evidence/compressed-blind/returns`。

## 复现

在项目根目录运行。已有逐题预测和生成缓存可直接复算；以下命令无需重新启动模型服务。

```powershell
foreach ($dataset in 'movie','movie_schema','restaurant','simr') {
    ./.venv/Scripts/python.exe scripts/decision_reader.py $dataset score
}
./.venv/Scripts/python.exe scripts/decision_analysis.py
./.venv/Scripts/python.exe scripts/review_human.py
./.venv/Scripts/python.exe scripts/decision_blind.py
./.venv/Scripts/python.exe -m unittest discover -s tests -q
```

如需重训 Pivot，运行 `scripts/decision_pivot.py` 后运行 `scripts/decision_ticket.py`，均用项目虚拟环境。环境使用 onnx 1.23.2、项目已有 ONNX Runtime 和 tokenizers，BERT 的源权重为 Xenova/bert-base-uncased 的 model_quantized.onnx 和 tokenizer.json，项目中已保存并校验。用 `decision_reader.py movie prepare`、`restaurant prepare` 和 `simr prepare` 重建提示。生成新的响应时，在另一个结果副本中移出对应缓存，按下述命令在独立终端启动本地服务，再从项目根目录运行对应的 score 命令。权重来自 Ollama 注册表 qwen2.5:7b 的模型层，核对 SHA-256 后加载；本次采用 llama.cpp b6330 Vulkan、4 路并发，部分餐厅请求及后续补充实验于重启后用 2 路服务槽。重用缓存会重现报告中的输出。GPU、服务分批和量化实现可能影响重新生成结果。

```powershell
cd data/external/review-reader
./llama-server.exe -m qwen7b.gguf --alias 2bada8a7450677000f678be90653b85d364de7db25eb5ea54136ada5f3933730 -ngl 99 -np 2 -c 6144 -t 4 --host 127.0.0.1 --port 18757
```

## 投稿前优先完成的验证

第一步是比较独立读者能否仅凭压缩文本恢复场次。第二步是在开发数据上只增加一个新对照：替换最近消息前，要求保留电影、影院、场次等已获支持的必填值，并核验最终决定是否覆盖先前信息。分别统计场次找回和其他字段丢失。第三步是在新的、同时含改口和未改口的独立样本上预先确定主要覆盖率和场景分组，锁定方法后一次性评分。若方法仍缺乏稳定优势，可把论文聚焦在历史预算、证据保留和订单风险之间可复现的失效条件。
