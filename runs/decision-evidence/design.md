# 运行前固定的比较设计

电影票使用原主测、复验队列作为事后检验。主要比较为相同的开发集 20% 提交覆盖率目标下，确认与改口选择相对最近消息的条件错单率差。保留 0.5 阈值结果，列出各自实际覆盖率，同时检查候选及提交。128 token 只计序列化历史，当前用户消息总是可见。对照还包括原字段选择、值提及后的相邻回复和重新训练的 Pivot。场景整组配对抽样 10,000 次，区间按指标分别计算。

Pivot 按原论文采用冻结的 bert-base-uncased、前一句与当前句拼接、256 token 上限和两层 MLP，训练 2 轮，AdamW 学习率 0.00003。量化 BERT 取末层 CLS，隐藏层宽 128，batch 32，种子 42。在以前已使用的 SGD 训练分片中哈希抽取 256 段无餐厅服务的对话，状态是否发生任意字段变化作为训练标签。系统轮沿用先前状态。TicketTalk 缺少逐轮状态监督，使用跨语料权重。本文按 128 token 打包，原文的比例词数预算、样本和权重与本实验不同。[Park 等](https://aclanthology.org/2026.findings-emnlp.719/)

第二业务使用 SGD 官方训练集未用于先前两组实验的分片 003, 011, …, 123。每段对话仅选最后一次 Restaurants_1 的 ReserveRestaurant 调用，要求调用前为用户消息。排除与旧分片及 dev/test 已接触的 ID 或调用前公开对话相同的样本，按固定哈希排序取至多 96 段。筛选只用调用类型、数据来源和对话标识，不按方法结果抽样。已接触该餐厅服务，检验的是新对话上的整单恢复。推理时已知调用模式，仅显示历史和当前用户消息。使用模式要求的所有必填字段判断是否提交，用参数字典完整匹配评分。日期及人数按服务模式说明，大小写和首尾空白归一化。按官方原始参数评主指标，另报告必填项同时匹配、补全模式默认值后的匹配。

本地 Qwen2.5-7B 在相同餐厅对话比较 recent、adjacent、pivot、decision，另列完整历史以估计读取上限。TicketTalk 按旧生成式实验的 96 个固定样本比较全部五种压缩方法，使用原模型实验的系统提示。采用贪心生成、温度 0、128 输出 token，固定权重 SHA256 为 2bada8a7450677000f678be90653b85d364de7db25eb5ea54136ada5f3933730。本项按字段完整性提交，不沿用传统读取器阈值。所有回放均在本地进行。

完整文本的 48 段继续由 A/B 独立标注。三位另外的读者 D/E/F 各阅读每条对话的一个压缩版本，在每位读者内 recent、field_support、decision 各占 16 条，每条对话的三个版本由三位不同读者判读。协调人持有对应表。用独立完整文本裁决作为参考，记录场次一致、无法判定和不同场次，报告完整文本无法判定数。
