# 真实语义检索、消融与运行开销

所有结果均使用修复后的 TicketTalk 对话时序和 CSV 引号解析。评测 ID 与修订主实验逐个对应。每个方法使用同一读取器、同一整单校准模型和 0.5 提交阈值，历史上限为 128 token。留出集已用于上一版研究，本组为事后扩展比较。字段证据、最近消息和 BM25 的每一条结果均与修订主实验校验一致。[样本划分](../review-chronology/protocol.json) · [本组协议](protocol.json)

## 来源与实现

预训练语义检索使用 all-MiniLM-L6-v2 的官方 ONNX AVX2 8 位量化模型。每条独立消息经编码、均值池化与 L2 归一化后得到 384 维向量。检索查询使用当前用户的话，加上固定的英文购票任务和字段说明。按余弦相似度排序，依次选取预算内可容纳的完整消息。混合检索以相同权重融合语义排名和时间排名，倒数排名融合的常数固定为 60。模型、查询说明及融合权重均未在留出集调优。该实验补充了实际预训练双编码器，尚未复现 Pivot 的状态变化监督和 DiCoS-DST 的训练目标。不同方法共享的校准器来自最近消息、BM25、候选值优先和字段证据四个原有分支，其置信度向新检索器的迁移本身会影响提交率。[模型和版本](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2/tree/1110a243fdf4706b3f48f1d95db1a4f5529b4d41)

|---|---:|---:|
| 最近消息 | 93 / 7 / 370 | 186 / 11 / 770 |
| BM25 | 60 / 10 / 400 | 127 / 17 / 823 |
| MiniLM 语义检索 | 10 / 3 / 457 | 14 / 14 / 939 |

| 可选字段纳入阈值 0.7 | 109 / 28 / 333 | 215 / 41 / 711 |

去除增量更新后，提供了相同字段和值的早先消息仍可进入历史。在主测中该消融与完整方法均有 106 个正确订单，少 12 个错单。复验正确订单少 4 个、错单少 14 个。可选阈值消融同时更新“拟填字段数”这一整单置信度输入，使用原先的校准模型；提高纳入门槛仍可能让更多订单通过提交阈值。各比较均为探索性分析，配对差异与未校正检验另存。[质量指标](quality.json) · [主测逐题](test-details.jsonl) · [复验逐题](replication-details.jsonl)

## 单请求端到端成本

本机 Intel Core i7-14700HX、ONNX Runtime 1.24.4、CPU 2 个编码计算线程。取主测中 ID 的 SHA-256 值最小的 64 段，各方法运行顺序随机。计时从解析原始历史字符串开始，覆盖文本处理、候选搜索、排序、真实 tokenizer 预算、参数读取和置信度计算，以及 SQLite 的建表、条件写入和读回。最近消息、BM25 和两个语义基线只对选中的消息计算参数读取分数，字段证据选择先扫描全部文本并复用计算结果。请求冷态清除提及缓存与密集向量缓存，但模型已经加载；热态指同请求立即重复。耗时均不含训练、磁盘加载数据、用户交互和网络。单独初始化 ONNX 含校验模型及第一次导入，约 1.01 秒。

| 方法 | 请求冷态 p50 / p95，ms | 同请求热态 p50 / p95，ms |
|---|---:|---:|
| 最近消息 | 4.75 / 6.81 | 4.79 / 6.60 |
| BM25 | 4.78 / 6.60 | 4.69 / 6.30 |
| 字段证据选择 | 6.65 / 8.75 | 6.41 / 8.86 |
| MiniLM 语义检索 | 157.55 / 211.02 | 4.69 / 6.15 |
| MiniLM 与最近消息的排名融合 | 161.33 / 220.60 | 4.99 / 6.99 |

与最近消息相比，字段证据选择的冷态中位数增加约 1.90 ms。这是单机离线实测。并发负载、缓存命中率、真实数据库和下游模型会改变生产表现。[计时元数据与代码摘要](timing.json) · [64 段原始耗时](timings.jsonl)

## 复现

项目根目录执行以下命令。预训练权重和兼容的本地 ONNX CPU 运行时已存放在本实验目录下。全量实验会重训共同的读取器，使用修订主实验保存的测试 ID 和参考结果作一致性校验。

```powershell
.\.venv\Scripts\python scripts\review_benchmarks.py
.\.venv\Scripts\python -m unittest discover -s tests -p test_review_benchmarks.py -q
```

重新建立干净环境时，在项目虚拟环境安装 `onnxruntime==1.24.4`，从上述固定模型版本取得 `tokenizer.json` 和 `onnx/model_quint8_avx2.onnx` 放入 `runs/review-benchmarks/encoder`。脚本在运行前核验两个文件的 SHA-256。
